# app/: TRIO as an fm1-base app

| File | What |
| --- | --- |
| `app.h` | The app's settings (name, block size, the store's objects) and its half of the contract with fm1-base |
| `app.c` | The screen, the controls, the settings, MIDI in, and the glue to the engine |
| `dsp/` | The engine (`trio.c`), the networks (`trio_nn.c`, the weights in `trio_w.h`) and the sound (`voice.c`) |
| `fm1.toml` | Build and site settings: name, package identity (FM-1_52), USB names, the -O2 units, tagline, credits |
| `words.tsv` | The screen reader's words (fm1-reader) |
| `tests/basic.txt` | Host simulator checks: the knobs, the feel, the mix page, saving across a reboot, the keys, the screen reader, Bluetooth MIDI (a computer, a device on SEL's page, on and off) |
| `tests/band.txt` | The band: Autumn Leaves' A section four times round at 140. It checks that the chords are heard, the form is learned, the band keeps going when the player stops, and no beat is missed. Generated by `tools/make_scenarios.py` |
| `tests/teach.txt` | EDIT, teaching the bass: a walking line taught over the form (over MIDI, then on the keys), learned, and how often the bass plays it after; kept across a reboot, taught while stopped, forgotten. Also generated |
| `tests/screens.txt` | The manual's screenshots (`docs/img`), also generated |
| `web/emu/` | The emulator page's own part: MIDI from a keyboard on the computer (Web MIDI) |
| `docs/MANUAL.md` | The manual |
| `site/landing.md` | The site's front page |

From the repository's root: `./build.sh` (the firmware), `./build.sh --host` (the simulator), `./build.sh --web`
(the emulator), `tests/run_tests.sh` (every test).
